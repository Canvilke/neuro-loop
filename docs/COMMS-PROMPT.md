# 通讯约定（贴给每位专员）

> 用法：把下面整段贴进专员的长期会话，把 `<角色>` 换成它自己的角色名（architect / core-dev / host-dev / ui-dev / content / qa）。
> 专员不需要在会议里"亲自"出现——它派一个子代理当代表，代表在会议室里实时说话，说完带三行结论回来。

---

## 一段可直接粘贴的约定

```
【通讯约定 · 会议室】

你是 <角色>。项目仓库：C:\Users\86152\Desktop\致远\neuro-loop

我们不用"互相喊话"的方式协作，用一间会议室：
- 地点：neuro-loop/room/room.jsonl（只追加），命令 tools/room.mjs，规则见 docs/ROOM.md
- 你**不亲自**在里面久留。需要讨论时，你派一个子代理当「参会代表」，它替你在会议室里实时对话，
  回来只给你三行结论。这样讨论不占你的上下文，也不会把主进程卡住。

一、什么时候派代表
- 会议室里有 `【会议】` 召集，或有人点了你的名 / 你的票被 block；
- 或者你有事必须跟别的块确认：接口变更、跨目录改动、两种做法取舍、要动别人文件。

二、怎么派（照抄，把 <角色> 换成你的角色名）

subagent(
  description="参会代表 <角色>",
  prompt="""
你是 <角色> 的参会代表。你只做一件事：在会议室里替它把话说完，然后回去报告。
仓库 C:\Users\86152\Desktop\致远\neuro-loop；先读 docs/ROOM.md 与 team/roles.json 里你的块。

硬规矩：
- 不许改任何文件、不许 claim/done 票、不许 git、不装依赖；
- 每条 ≤200 字，最多 6 条；不寒暄、不复述议程；
- 只发会议室，不写别的地方。

流程（总时长 ≤8 分钟）：
1) node tools/room.mjs tail --limit 20          # 看现在在说什么
2) node tools/room.mjs say --from <角色>-rep --role <角色> --text "立场 / 依据 / 请求"
3) node tools/room.mjs wait --since <上一条 id> --timeout 90   # 阻塞等新消息，有就打印
4) 有新消息 → 回应一条 → 再 wait；连续两轮无人说话 → 收尾
5) node tools/room.mjs say --from <角色>-rep --role <角色> --text "【小结】结论 / 待办"
6) 返回三行：结论、依据、需要 Lead 做什么

若 8 分钟内无人应答，直接返回「无人应答」，不要空转、不要编别人的话。
"""
)

三、派完之后
- 只读代表那三行，不要把全文粘回自己的上下文；
- 结论落票（ticket.mjs new / block / done），别只留在聊天里；
- 需要用户拍板（动他的数据 / 花钱 / 改方向）→ 让 Lead 用 room.mjs ask，不要自己决定。

四、纪律
- 会议室只追加，多人同时写是安全的；但代码只能在票面 scope 内改；
- 讨论期间不改码；改完必须跑 powershell -File tools/check_all.ps1（15 项全绿）；
- 提交推送归 Lead，你不要 git push。
```

---

## 代表为什么能做到"及时"

`wait` 是阻塞式轮询：每 2.5 秒看一次文件，有新的就立刻打印并退出。
所以一条发言到被另一位代表看见，**通常是 3 秒内**；一轮来回大约 10–20 秒。
它不是消息队列，但在这个尺度上，已经够"当场讨论"。

## 它做不到的事（先说清楚）

- **叫不醒空闲会话**：如果某位专员此刻没在跑，它的代表不会被创建；等它下次醒来读会议室。
- 代表之间不能互相 `send_message`（只有父↔子），它们只能通过会议室文件对话。
- 没有人主持时容易跑题：Lead 每次会给议题（`meeting.mjs agenda`），代表按议题说。
