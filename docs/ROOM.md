# 会议室（Room）

夜间协作时的对话记录。名字叫会议室，因为它只干一件事：**在动代码之前把话说清楚**。
票单管"做什么"，总线管"交付/回执"，会议室管"为什么这么定"。

---

## 1. 一条消息长什么样

```json
{"id":"m3f2a1b9","at":"2026-11-13T00:31:02.415Z","from":"lead","role":"architect","kind":"say","text":"今晚先收尾 T-0012","ref":null}
```

| 字段 | 说明 |
|---|---|
| `from` | 说话者，`/^[a-z0-9][a-z0-9_-]{0,23}$/`；子代理用自己的名字，IM 转发用 `wx` |
| `role` | 可选，六个角色之一（architect / core-dev / host-dev / ui-dev / content / qa） |
| `kind` | `say` 发言 · `ask` 提请拍板 · `decision` 拍板结论 |
| `ref` | `decision` 必填，指向它回答的那条 `ask`；也可挂票号（`T-0013`） |
| `id` | 8–16 位，追加即定，不可改 |

**只追加**：没有编辑与删除。说错了就再说一条"更正"，历史保留——这是可追溯的代价。

## 2. 三个动作

```bash
# 说话（不需要等人）
node tools/room.mjs say --from lead --role architect --text "T-0012 我接手，别碰 src/045-net.js"

# 提请拍板（只有这里会惊动用户）
node tools/room.mjs ask --from qa --role qa --text "要不要现在补边界回归？"

# 拍板（回答某一条 ask；用户不在时 lead 代拍，但必须写清依据）
node tools/room.mjs decide --ref m3f2a1b9 --text "补，放进 T-0017"

# 看
node tools/room.mjs tail --limit 30
node tools/room.mjs asks
```

退出码：`0` 成功、`2` 用法错、`3` 业务拒绝（`decide` 指向不存在的 ask 等）。

## 3. 界面

侧栏只有一个入口「认知终端」，里面的 **会议室** 页签：

- 顶部：待拍板条数 + 刷新
- 中间：时间线（`[说]/[问]/[决]` 三种颜色，`ask` 有「待拍板」小标）
- 待办区：每条 open ask 一个「拍板」按钮（弹窗写结论）
- 底部：输入框，回车发言；「请拍板」把这句话变成 `ask`

面板**不轮询**——手动刷新或切页签重新挂载才拉一次。原因：`setInterval` 会让无头测试挂住进程（信件、控制台都踩过）。

## 4. 什么时候用哪条通道

| 场景 | 用哪个 | 为什么 |
|---|---|---|
| "我完成了 T-0012，改了哪三个文件" | 总线 `sub` | 结构化、可计数未读 |
| "我准备这么改，有异议吗" | 会议室 `say` | 需要理由，不需要回执 |
| "这个必须用户决定" | 会议室 `ask` → 频道通知 | 只有 ask 会提醒人 |
| "票面范围要变" | 票单 `block` + 会议室说明 | 票单是事实，会议室是理由 |
| 跨会话交接 | `docs/BOOTSTRAP.md` + `mail` | 新人先读文件，不读聊天 |

---

## 5. 边界（诚实写在这里）

- **会议室不会叫醒任何会话。** 它是一份所有人都能读的文件；谁醒着谁看。真正能双向唤醒的只有 lead 自己 spawn 的子代理。
- **不替代票单。** 会上说的结论要落成票（`ticket.mjs new`），否则第二天没人执行。
- **不做富文本/附件。** 2000 字以内纯文本，够用；要长内容写进 `docs/` 再挂链接。
- 用户不在场时，lead 可以代拍，但 `decide` 必须写依据；出现"要不要动用户数据/花钱/改方向"三类问题，只能挂起等他。
