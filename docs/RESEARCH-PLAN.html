Neuro-Loop 数据模型 v2
参考研究、取舍与实施计划

把"一个人怎样从看懂到想起、再到考场里做得出来"拆成可以存储、可以测量、可以重建的结构。
版本 v2.0 · 2026-11-10 · 面向：项目负责人审阅 · 依据：现有 `neuro-loop` 代码与 `%USERPROFILE%\.dsh\neuro-loop\` 的真实事件流
性质：研究综述 + 结构提案。文中"借鉴"与"创新"分别标注，不把已有一切说成原创。

0. 摘要

现有系统（v1）解决了"看得见"：星图、分层、启动序列、事件流、跨会话信箱。但它回答不了三个问题： 一道题为什么被判为会、多快能想起来、以及明天该复习哪一条。 v1 的数据结构只有"考点 → 命中/失误计数"，缺少题目、方法、时间三个维度，因此再好看也只是仪表盘。

本提案给出四层、五实体、六个不变量与四个算法。核心是三条判断：

  1. 原子是"一次判定"，不是一道题。同题在不同模式（认出 / 重推 / 实做）下是不同的证据。
  2. 方法（method）必须是一等公民。它是跨章节的可迁移程序，也是我们所说"记忆向量"的可操作定义： 方法 = 在考点空间上的稀疏权重 + 可复述的判据。
  3. "KV cache"应当被真的实现成一层带衰减的缓存，而不是比喻。命中走缓存（快、易假阳性），未命中走重推（慢、更可靠），两者都记时间。

与已有系统的关系：教育测量（BKT、IRT、知识空间）提供掌握度与判分；间隔重复（SM-2、FSRS）提供调度； LLM 训练与推理（MLA、KV cache、稀疏注意力、MoE、RLHF）提供压缩、命中、稀疏与遗忘的工程隐喻； 智能体记忆（MemGPT、Zep/Graphiti、Mem0、HippoRAG）提供分层存储与多跳检索的实现先例。 本方案的创新点在于把四者拼在一个可被单人承受的数据量上，而不是发明新算法。

1. 原构想的形式化

1.1 四层与一次考试的过程

原文章把学习过程映射为大模型的训练与推理。落到数据上，一次"考试"其实是：

题目文本 ──编码──▶ 考点集合（稀疏 top-k） ──检索──▶ 方法集合（top-m）
                                        │
                    命中缓存 ◀───────────┴──────────▶ 现场重推
                       │                                  │
                    步骤输出（快）                     步骤输出（慢）
                       └────────── 判定（对/半/错/假阳性）──────────┘

四个可测量的量由此产生：命中率（考点是否被想起）、准确率（想起后是否做对）、 还原时间（从想起到写出步骤耗时）、压缩率（方法判据字数 / 完整步骤字数）。

1.2 v1 缺什么

能力v1 现状后果
题目作为实体不存在；只有考点计数无法回答"这类题我做过几道、错在同一处吗"
方法作为实体有 10 张卡，但未接入判定与调度方法无法被复习，也无法解释"为什么这题该用这个"
时间维度只有 dueAt，无耗时"想得起来但很慢"无法与"想不起来"区分
缓存层无"熟题秒出"与"现场推导"没有分别记录，假阳性无法被识别
稀疏性考点图接近全连接（每科 16 条边 / 11 节点）检索没有取舍，等于没有注意力

3. 取舍：借鉴什么，明确不做什么

取理由舍理由
BKT 式掌握概率 + FSRS 式 (stability, difficulty)参数少、可解释、单人可跑DKT 类深度模型需要千级学生数据，且不可解释
Q-matrix 的稀疏关联（每题 2–4 考点）强制取舍，才谈得上注意力全连接知识图谱"漂亮但没用"：任何两点都有边等于没有边
KV cache 的真实实现（命中/未命中/淘汰）把"熟"与"会推"分开测量把缓存当装饰性比喻无法验证，也无法产生假阳性信号
双时间轴（记录何时学、何时有效）回看"当时会不会"独立图数据库单人数据量用 JSONL 足够
事件溯源 + 可重建投影已有实现、可审计、可回滚直接以投影为真源投影损坏即数据丢失

4. 提案：CNS v2（Cognitive Node Schema）

一句话：把"会一道题"拆成四个可分别记录的事实——哪些考点（稀疏 2–4 个）、用了哪个方法（1–3 个）、是想起还是重推（mode）、花了多久（durationMs）；掌握度、到期、缓存全部由这些事实算出，不单独存。

4.1 五个实体

concept   考点：学科内的最小可判定单位
  { id, subject, block, name, prereq[], core, traps[], methodHint[] }

method    方法：跨章节的可迁移程序（本项目称"记忆向量"）
  { id, claim(≤40字), judge(何时用), steps[], instances[], traps[],
    concepts{conceptId: weight 0..1}, signature[], stability, difficulty,
    source: self|ai, verified: bool, compression }

problem   题目：一次具体任务
  { id, source, ref(文本/照片路径), concepts[{id,w}], methods[{id,w}],
    difficulty, answerRef }

attempt   一次判定（事件，append-only）
  { id, at, problem, mode: recall|recon|solve, outcome: hit|partial|miss|fp,
    durationMs, hintLevel 0..2, note }

cache    缓存项（派生，可重建）
  { key(problem指纹), problem, stepsRef, hits, lastHitAt, ttlSec, state: fresh|stale }

4.2 六个不变量

  1. 单一真源：只有 attempt（及少量内容写操作）是事实；掌握度、缓存、到期全是投影，删掉必须能重建。
  2. 稀疏上限：任一 problem 的 concepts ≤ 4、methods ≤ 3；超出即视为"这题该拆"。
  3. 方法必须有判据：claim 与 judge 不得为空；只有名字的方法不算方法。
  4. 命中与准确分离：任何聚合指标不得把 recall 与 solve 混算为一个"掌握度"。
  5. 假阳性是查询：不落字段。定义为"该考点/方法 hit 率高、但 solve 准确率低且错因重复"。
  6. 时间可解释：durationMs 必须记；没有时间的"会"等于没有测。

4.3 稀疏检索与打分

score(problem, concept) = w(problem→concept) × mastery(concept)
mastery(c) = σ( (hits - λ·misses) / (hits + misses + 1) ) × decay(Δt; stability(c))
decode(problem):  top-k concepts (k≤4) → top-m methods (m≤3)
若 cache[fp(problem)] 为 fresh → 走缓存，记 mode=recall, durationMs=命中耗时
否则 → 重推，记 mode=recon, durationMs=完整耗时；完成后回写 cache

λ 是"错误惩罚"，初始取 1.5；它直接对应 RLHF 里的负样本权重思想，但我们不用梯度，只用可解释的计数衰减。

4.4 缓存淘汰与假阳性

ttl(fp) = base × stability(method*)        base≈3 天
命中且 solve 判对  → hits+1, stability×1.35 (上限 60 天)
命中但 solve 判错  → 记 fp；stability×0.6；cache 立即置 stale（下次强制重推）
连续两次 stale     → 从缓存移除，转回 recon

这一条把"我以为我会"变成结构上可检测的事件：缓存命中 + 实做失败 = 假阳性，而不是靠自评。

4.5 写入管线与分层上下文（形态照抄，判据自定）

写入四步（每次录入一道判定都走同一条路，保证可审计）：

  1. 抽候选：从一次录入里抽出考点 id（2–4）、方法 id（1–3）、模式、耗时、结果。
  2. 近邻比对：取同考点最近 k 条判定与当前缓存项，判断这次是重复命中、推翻旧结论还是首次出现。
  3. 写事件：追加一行 jsonl（只追加，不改历史）；若是"推翻"，旧缓存项标 state:"stale" 并指向新事件，不物理删除。
  4. 更新投影：重算该考点/该方法的掌握、到期、缓存三组派生值，写回 state.json。

分层上下文（借 MemGPT 的三层形状，但检索由系统触发、不交给模型自觉）：

层内容容量/触发
core本周单元、当前方法卡、今日两张纸的元信息硬上限 ~2k 字，直接进提示
recall全部判定的全文索引（可按考点/方法/日期过滤）检索时取 top-k，带 as-of 时间
archival已折叠的旧判定、历史错题原文只按 id 取，不参与默认检索

三个"防蠢"约束：① 公式、定义、教材原文标 protected，改动需显式确认并留旧值；② 摘要按块失效——某考点变了，它的摘要与所属单元摘要是脏的；③ 反馈记三元组 (原答, 改后答, 理由)，只记对错会把"蒙对"当成会。

5. 指标与实验设计

指标定义用途目标（首月）
Hit Raterecall 模式 hit / 该考点 recall 次数是否"想得起来"≥ 0.65
Acc Ratesolve 判对 / solve 次数是否"做得对"≥ 0.55
FP Rate(hit 且 solve 错) / hit假阳性比例逐月下降
Recon P50/P90重推耗时中位数 / 90 分位还原速度同章下降 20%
Compressionclaim 字数 / steps 字数是否真的压过≤ 0.25
Due Adherence当天完成 due / 当天 due调度是否可执行≥ 0.7

5.1 三段式验证（不需要新数据）

  1. 回放：用已有 events-*.jsonl 重建，比较 v1 与 v2 对同一天的"该复习什么"的差异；差异必须能解释。
  2. 消融：去掉缓存层 / 去掉方法层 / 改 top-k=全部，看 FP Rate 与 Recon 时间的变化。
  3. 前瞻：连续 7 天按新调度执行，记录 Due Adherence 与 FP；不达标就回退参数，不改结构。

不做：A/B 分班、题库规模扩张、以刷题量作为指标。单用户系统里这些只会制造噪声。

6. 实施路线

步交付验证依赖
S1schema + 迁移脚本（v1 事件 → v2 实体）回放 100% 可重建；删投影可恢复无
S2POST /neuroloop/attempt（写 attempt）与 GET /neuroloop/decode?problem=（top-k 检索）host 测试新增 ≥ 10 条；错误码齐全S1
S3缓存层：ttl、stale、fp 检测；界面显示"缓存命中/重推"构造一次"命中但错"→ 自动标 fpS2
S4调度换 FSRS 式；due 列表接进「今天」面板Due Adherence 可算S3
S5方法层接入：录入方法卡时给出 concepts 权重，判分时可选方法10 张卡全部有 concepts 与 stabilityS2
S6星图读 v2 投影（方法星层）视觉验收（用户截图）S5

排序理由：先让数据可信（S1–S3），再让调度有用（S4），最后才是视觉（S6）。反过来做等于给不可信的数据化妆。

7. 风险与反面清单

  • 过度建模：五个实体已接近单人系统的上限。再加"情绪/环境"只会让录入停摆。
  • 假阳性定义过窄：若长期没有 fp，先怀疑录入太少，而不是庆祝。
  • 参数不可信：FSRS 类参数需要足够日志；首月一律标 calibrated:false，用保守默认值。
  • 方法卡膨胀：10 张够用；每加一张必须能说出"它挡掉了哪类错"。
  • 视觉先行：星图是读投影的，不是真源。任何"看起来对"都不能替代 attempt 记录。
  • 不可回退：每次结构变更必须留下回放脚本，否则半年后无法解释历史数据。
